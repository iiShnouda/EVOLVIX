# Evolvix (SKB) — Project map

**Read this first.** It says where everything is, what each screen does and how to run and
test, so a new session can start working straight away. The rules are in `CLAUDE.md`; the
domain model in `DOMAIN.md`; the history of decisions in `PROGRESS.md`. Keep this file current
when you add a page, controller, entity or test suite.

_Last updated: 2026-10-02._

---

## 1. Working conventions (owner's standing instructions)

- **Commit and push straight to `main`** (no PR):
  `git fetch -q origin main && git rebase -q origin/main && git push -q origin HEAD:main`.
  Pushing `main` deploys to Render automatically (`render.yaml`).
- **Reply to the owner in Arabic** (Egyptian, plain). Code, comments and commit messages stay in English.
- Comments quote the owner's decision with its date, e.g. `(owner, 2026-10-02: "…")`.
- Never show anyone the server's or system's files, paths or internals (error messages are short
  and generic: `lib/errors.ts` shows only `error.<code>` texts, never the server's message).
- Run `prettier --write` **only on files you created or edited** (never on the whole repo / old tests).

## 2. Dev environment (cloud container)

The container does not keep running services between restarts. Bring them up like this:

```bash
# PostgreSQL 16 (data dir already exists; remove a stale lock first if it refuses to start)
rm -f /tmp/.s.PGSQL.5432.lock
sudo -u pguser /usr/lib/postgresql/16/bin/pg_ctl -D /var/lib/postgresql/skbdata \
  -o "-p 5432 -c listen_addresses=localhost -c unix_socket_directories=/tmp" -l /tmp/pg.log start
# DB user: skb / skb_dev_password. Any new database name is created + migrated + seeded on start.

# Build the API (Release) and run it on a database + port
export PATH="$PATH:/usr/lib/dotnet"; export DOTNET_ROOT=/usr/lib/dotnet
cd apps/api/src/SKB.Api && dotnet build -c Release -v q
ASPNETCORE_ENVIRONMENT=Development \
ConnectionStrings__Default="Host=localhost;Port=5432;Database=skb_t5;Username=skb;Password=skb_dev_password;Pooling=true;Maximum Pool Size=50" \
RateLimit__UserPerMinute=100000 RateLimit__IpPerMinute=100000 ASPNETCORE_URLS=http://localhost:5080 \
  dotnet bin/Release/net10.0/SKB.Api.dll          # run in the background (long timeout)
# stop: kill $(pgrep -f "^dotnet bin/")   — rebuild after every server change, a stale build serves the SPA HTML for new routes

# Web (Vite proxies /api → localhost:5080)
pnpm -C apps/web exec vite --port 5173 --host 127.0.0.1

# Typecheck
pnpm --filter @skb/shared build && pnpm -C apps/web exec tsc --noEmit -p .
```

- **Migrations:** `cd apps/api/src/SKB.Api && dotnet ef migrations add <Name>`. A new NOT NULL
  column on an existing table needs a default: arrays `defaultValueSql: "'{}'::text[]"`, numbers
  `defaultValue: 0` — otherwise the Render deploy crashes on existing rows ("contains null values").
  Backfills go in the migration as `migrationBuilder.Sql(...)`.
- **Playwright screenshots:** `NODE_PATH=/home/user/SKB/node_modules`, executable
  `/opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell`. Sign in as
  `owner@skb.local` / `ChangeMe!Owner123`. The app reopens the last page after sign-in, so
  `goto('/dashboard')` explicitly. Check desktop (1440), tablet (820) and phone (390) widths.
- **Seeded users:** `owner@skb.local` (Owner), `mona@skb.local` (Accountant),
  `karim@skb.local` (Sales), `sara@skb.local` (Inventory) — same dev password.

## 3. Tests (`scripts/checks/`)

End-to-end checks against a running server; each creates its own data. Table of every suite and
what it covers: `scripts/checks/README.md` (add a row for every new suite).

```bash
BASE=http://localhost:5080/api node scripts/checks/paystates.test.mjs   # one suite
# all, in this order (limits first: it sets the Settings the others expect; admin last):
for t in limits catalog images charges parties costs departments orders codes invoices branding delivery devices \
         ledger statements notes cheques money staff payroll access pricing quotes returns additems \
         dashboard story dates ids scope handovers paystates time system tree chat profit places server admin; do
  BASE=http://localhost:5080/api timeout 600 node scripts/checks/$t.test.mjs > /tmp/t-$t.log 2>&1
  echo "$t $? $(grep -E 'passed, [0-9]+ failed' /tmp/t-$t.log | tail -1)"
done
```

`chat` needs the stand-in model server first: `node scripts/checks/fake-ollama.mjs &` (the dev
`Assistant:Endpoint` is http://127.0.0.1:11434). `reader.test.mjs` needs no server. `clean.test.mjs`
needs its own server on an EMPTY database started with `Seed__Demo=false`.

`lib.mjs` has `login`, `check`, `eq`, `ok`, `summary`, `companyToday`, `addDays`. Use a fresh
database (e.g. `skb_t6`) for a full run; `ids` and `admin` want one.

### 4.2 Shell (`components/shell/`)

- `GroupTree.tsx` (in `components/`) — department tree: `GroupPicker` (department → group → group… level by level, used in the purchase screen, item editor, item finder, inventory), `GroupsSetup` (the setup tab "التفريعات"), `groupLabel`, `childrenOf`.
- `ScanButton.tsx` (in `components/`) — "read from a photo" (`ai:scan`) for the purchase screen (supplier, lines matched to items by the smart search, else new lines read by `readItemName`) and the notes screen (cheque rows).
- `Shell.tsx` — adaptive shell: desktop sidebar (collapsible), tablet rail, phone bottom tabs +
  More (on a phone, language + light/dark sit in More). Filters nav items by permission (`permission` / `anyOf`). Renders `BackLink` above pages.
- `BackLink.tsx` — "العودة إلى <page>" per tab: only when a button on a page led here (menu links pass `FROM_MENU` state and reset the trail); `pageName()` names a path.
- `GlobalSearch.tsx` — top-bar search (desktop/tablet; Ctrl+K or `/`) and `PhoneSearch` (header icon → sheet): customers/suppliers/carriers, sales and purchase invoices by number, items, and pages/actions — each only with its view permission.
- `Tabs.tsx` — **open pages (tabs)**: `TabsView` replaces `<Outlet/>`; every tab's page stays mounted via `useRoutes(tabRoutes, tab.loc)` (routes handed over by `setTabRoutes` in `App.tsx`); the shown tab follows the address bar, switching navigates with `TAB_SWITCH` state. `+` opens a tab, Ctrl/middle-click on a menu item too; split screen (beta, desktop) shows two tabs side by side. The app's ONE `useBlocker` lives here (`guards` from `workDraft.ts`); tab addresses are kept in the `session:tabs` preference. State in `lib/tabs.ts` (`useTabs`, `useTab`, `TabContext`). Each `TabPane` wraps the router's navigation context: a hidden tab's navigation only moves that tab's own address, never the shown page.
  `NAV_ITEMS` or `EXTRA_PAGES` (add new non-menu pages there).
- `AccountMenu.tsx`, `NotificationBell.tsx` (bell + chime, live via presence hub),
  `ConnectionBadge.tsx`, `PrefControls.tsx` (language + light/dark).

## 7. Business rules that are easy to get wrong

- **Invoice payment state** (`DocumentLists`, owner 2026-10-02). Per party and document type,
  oldest first (IssueDate, then Number):
  - `Unit = GrandTotal − PaidDirect` (paid at the counter / COD counts directly).
  - `Newer` = Σ Unit of the party's newer invoices.
  - `Owing` = Balance (sales) or −Balance (purchases); returns, receipts, discounts lower it.
  - `Owed = clamp(Owing − Newer, 0, Unit)`.
  - `Deferred` = Σ NoteAllocations of pending cheques/notes on the invoice.
  - State, in order: `CANCELLED` / `AWAITING` / `COLLECTING`. Then if Owed ≤ 0: `CREDIT` (آجل, by cheque) when Deferred > 0, else `PAID`. Else Owed < GrandTotal → `PARTIAL`. Else younger than 24h → `DUE`, otherwise `UNPAID`.
- **Settlement discount:** `POST /settle-discount` (`vouchers:discount`): DSC- (customer) /
  DSR- (supplier) voucher, at most what is owed, allocated FIFO, cancel restores the balance.
- **Cash boxes:** main box (`IsMain`, one, owner picks), branch default box ("خزينة الفرع"), one box
  per warehouse. Handover holds the amount (`Held`) until received → transfer voucher.
- **Credit limits:** over-limit sales wait (`AWAITING`); receipts release them oldest first.
- **Dashboard periods:** `from`/`to`; trend daily ≤ 62 days else monthly; clamp to today.
- **Profit and loss** (2026-10-06): the main cash box is where money is gathered, not where it is
  earned — transfers and handovers are neither gain nor loss; expenses paid from it are general
  expenses, apart from any branch. Branches add up to the company total with the general row; the
  total equals the ledger income statement's net profit (its gross profit there includes other income).
- **Item codes** (2026-10-06): branch-warehouse-department-group…-NNNNN from the prefixes on the
  way down (`Catalog.NextCodeForAsync`); none → `ITEM-NNNNN`. **Barcodes**: a new item's base unit
  gets EAN-13 `20` + 10 digits + check (`Catalog.NextBarcodeAsync`) unless one is typed.
- **Search** matches every typed word in `SearchKey` (folded or by outline) or a group's name /
  keywords (whole subtree), then near matches (one slip ≤ 6 letters, two from 7).
- **Assistant** never writes data, never runs commands or reads files; only the app reaches the
  model server (no published port in docker-compose).
- **Names** one field as typed; **money** integer minor units; **days** via `CompanyClock`.

## 8. Adding something — checklist

1. Entity + migration (defaults for NOT NULL columns!) → DTOs in `Dtos.cs`.
2. Controller with `[Authorize(Policy = Permissions.X)]`, `.InBranches(User, …)`, audit on mutations,
   errors as `{ code }` with an `error.<code>` key in both dictionaries.
3. Permission in `Roles.cs` **and** `roles.ts`; types in `types.ts`; i18n keys in `ar.ts` + `en.ts`.
4. Hook in `lib/queries.ts`; page in `pages/`; route in `App.tsx`; menu item in `navigation.ts`; its main actions in `lib/quickActions.ts` (quick-action button)
   (or `EXTRA_PAGES` in `BackLink.tsx` for pages off the menu).
5. A test suite in `scripts/checks/` + a row in its README; run the related suites.
6. Check phone / tablet / desktop and AR (RTL) / EN; typecheck; prettier on edited files; push to main.
